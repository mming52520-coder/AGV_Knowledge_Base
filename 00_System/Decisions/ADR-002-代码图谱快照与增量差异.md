# ADR-002：代码图谱快照与增量差异

## 背景

最新代码需要与第一版代码图谱比较，而不是覆盖第一版。只依赖 Git 历史不足以在 Obsidian 中查看实体和关系演化，也无法区分源码变化、证据行号移动和抽取规则变化。

## 决策

采用“不可变 V1 基线 + 完整目标快照 + 人类可读差异”的模型。

- 完整 V1 固定为提交 `e8a1b3d` 和标签 `kg-code-v1-e8a1b3d`。
- V1 基线必须从现有图谱页面导出，不能重新扫描最新源码冒充 V1。
- 每个新代码版本先生成独立快照，再与 V1 比较。
- 新快照不修改 V1 页面，不批量替换 V1 的 `source_snapshot`。
- 每个完整机器快照可以生成只读的“版本实例投影页”，统一存放在该快照自己的 `Snapshots/<snapshot_id>/Entities` 目录。实例页必须由机器产物确定性生成，不能替代 `03_ROS` 中的逻辑实体页。
- 差异审核仍以 `Changes/<baseline>__<target>` 中的新增、修改、移除、关系与迁移记录为主；版本实例投影只用于独立浏览某一快照的完整图。
- 审核通过后只更新独立的“当前推荐快照”指针。

## 身份模型

- `entity_uid`：跨版本稳定逻辑身份，例如 `agv:ros:node:chassis_bridge`。
- `snapshot_id`：一次确定的代码扫描身份。
- `entity_fingerprint`：规范化语义字段哈希。
- `relation_fingerprint`：规范化关系集合哈希。
- `evidence_fingerprint`：来源路径、行号和文件哈希；仅证据变化不等于语义变化。

## 差异分类

- `added`：目标快照中新增。
- `removed`：同一扫描范围中不再出现；不自动删除 V1 页面。
- `modified`：语义字段发生变化。
- `relations_changed`：发布、订阅、依赖或控制关系变化。
- `renamed`：稳定实体发生名称或路径迁移。
- `deprecated`：源码或决策明确标记停用。
- `ambiguous`：存在多个候选或证据不足。

“删除”和“停用”不是同一状态。重命名候选未经确认不得静默合并。

## 重命名规则

1. 精确 `entity_uid` 优先。
2. 使用 Package、ROS 全名、接口全名和硬件型号等强键。
3. 使用人工确认的别名表。
4. 无强键时，候选分数至少 `0.92`、领先第二候选至少 `0.15`，并具有两个以上强证据，才列为高置信重命名候选。

## 未采用方案

### 扫描新代码后直接重写现有页面

拒绝。它会丢失第一版事实和人工判断，也无法审查删除与关系变化。

### 手工复制既有 Markdown 页面作为新版本

拒绝。手工副本会把旧结论伪装成新证据，也无法保证可复现。允许从已校验的完整机器快照确定性生成版本实例投影；投影具有独立目录、快照身份和来源哈希，且不覆盖逻辑实体页。

## 结果

- V1 可随时复原和浏览。
- V2、V3 可以连续比较。
- 每个快照既能独立浏览完整实体图，也能通过差异页查看演化。
- 每个变化都有 before/after、证据和复核状态。
- 回滚只移动当前指针，不删除历史快照。
